# Gothwad Browser — full audit + fix plan (2026-10-14)

Read this together with `AGENTS.md` (mission, hard rules, incident log). This file is the
*honest* state of the app: what is actually broken, what is only half-built, what the README
claims that the code cannot back up yet, and what has already been fixed in this pass.

Everything below was found by reading the code in this repo (130 Kotlin files, ~24.7k lines,
plus layouts/values/manifest). No issue was filed on GitHub at the time of writing
(`GothwadTech/browser` has 0 open issues), so this document is the issue tracker for now.

> ⚠️ **Verification limit:** this sandbox has no JDK and no Android SDK, so **nothing here was
> compiled**. Every change in this pass is small, self-contained and follows patterns already used
> in the repo, but the first real build on a device is still required. Use §6 checklist.

## 0. The one thing to fix before anything else: the licence story

Three statements in the project contradict each other, and one of them is legally dangerous:

| Where | Claim |
|---|---|
| `README.md` | "Copyright © Gothwad Tech. All Rights Reserved. **NO OPEN SOURCE LICENSE IS GRANTED**" |
| `values/strings.xml` → `open_source_notice` / `gothwad_tech_desc` | "**100% Open Source** Software · Zero Server Dependencies" |
| repo root | no `LICENSE` file exists at all, so the only terms a reader finds are the README's |
| About screen (`Settings → About`) | same "open source" text |

At the same time the code still carries fingerprints of the upstream project it is built on:

* `Config.HOME_PAGE_URL = "https://tvbrowser.phlox.dev/appcontent/home/"` (in `app/common/…/Config.kt`)
* `Config.TV_BRO_UA_PREFIX`, `package …tvbrowser…` style class layout, `webengine/webview/*`,
  `widgets/cursor/*` structure (upstream **TV Bro** by Fedir Tsapana, GPL-3.0-or-later).

This does **not** make the 3–4 months of work unreal — the phone layout, sidebar system, native
home, TV notepad, clipboard manager, D-pad cursor, etc. are genuinely new work on top. But GPL
work cannot be re-released as "all rights reserved, no licence": redistribution of a GPL-derived
app requires the GPL terms (source availability under GPL-3, retained upstream copyright notice,
no additional restrictions). Two practical consequences:

1. **Google Play / JioStore risk** — a DMCA or a policy rejection on a paid listing is much worse
   than fixing the notice now.
2. `REQUEST_INSTALL_PACKAGES` + `QUERY_ALL_PACKAGES` + "download APK" flows are also Play-sensitive
   (see §3.9 — `QUERY_ALL_PACKAGES` was removed in this pass).

**Action needed from you (I cannot decide this):** either (a) relicense the repo as GPL-3.0 with
upstream credit, keep the "Gothwad" branding and app-store listings, or (b) if you really want
proprietary, the app has to be rebuilt from scratch without the upstream code. Pick one and I will
do the mechanical cleanup (README + About + headers + `LICENSE` file + attribution NOTICE).

## 1. What "Chrome-like on phone" means here, and what was wrong

Chrome on Android is: **one address pill on top** (site-security icon · title/URL · mic) and a
**bottom toolbar** (back · home · new tab · tabs-with-count · ⋮ menu). Google-account / Lens /
"sign in" surfaces are *not* part of the requirement.

**Before this pass** (see `MainActivityUI.updateToolbarLayoutForOrientation()`, old version):
in portrait the code simply hid 5 buttons and crammed **Home, omnibox, +, tabs-badge, ⋮** into a
single 52dp row — ~400dp of widgets in 360dp of screen. The omnibox (`layout_weight=1`) collapsed
to a few dp wide, so the URL became unreadable and the mic/lock icons overlapped. Meanwhile
`llBottomPanel` (the bottom toolbar!) was already declared in `activity_main.xml` as a
**`0dp`-tall, permanently GONE `ConstraintLayout`** — the Chrome bottom bar existed as dead XML
and nothing was ever drawn in it. `hideMenuOverlay(hideBottomButtons: Boolean)` took a parameter it
never read, and `toggleMenu()` never toggled anything (it re-showed the header, so the "toggle
toolbar" keyboard shortcut in `ShortcutMgr.kt:206` was a no-op).

**Fixed in this pass (§4.1 for the exact diff summary):**

* real bottom toolbar in `activity_main.xml` (`ibBottomBack`, `ibBottomHome`, `ibBottomNewTab`,
  `flBottomTabsSwitcher` + `tvBottomTabCountBadge`, `ibBottomMenu`), 56dp, elevated, drawn over the
  page; the WebView container / home view / miniature overlay now use
  `layout_above="@+id/llBottomPanel"`.
* `isCompactChromeLayout()` (not-TV **and** `smallestScreenWidthDp < 600`) drives the two layouts.
  A 7–8" tablet is *not* treated as a phone, so TV/tablet keep the full D-pad header — that's the
  "PC view" the remote needs.
* top row in phone mode = omnibox only; `llTopTabBar` stays hidden on phones (it is a TV/desktop
  affordance).
* `updateBackForwardButtons()` also drives the bottom Back button, `updateTabCountBadge()` also
  drives the bottom badge, `focusDefaultNavigationElement()`/`showHomeScreen()`/`switchToTab()`
  focus the *visible* control via `requestHeaderFocus()` (a `requestFocus()` on a GONE button used
  to silently drop focus and freeze D-pad/keyboard navigation).
* `toggleMenu()` really toggles on TV/tablet, and `hideMenuOverlay()` keeps the phone bottom bar
  persistent (Chrome does the same while the address bar is not being edited).

Deliberate deviations from stock Chrome (documented, not accidental): no Google account chip, no
Lens, no "Search with Google" branding, no swipe-to-refresh, header does not auto-collapse on
scroll (the fixed header is an explicit AGENTS.md decision, `onScrollChange` says
"Header is permanently fixed at the top").

## 2. Findings — P0 (visible breakage / risk)

1. **Settings text was white on white in a light theme.** `view_settings_main.xml` had
   `android:textColor="#FFFFFF"` ×31 and `#38BDF8` ×25 on cards whose background
   (`google_card_bg`) is `#FFFFFF` in day / `#1B1B1B` at night → every label invisible in light mode,
   plus `SettingsRemoteSection.kt:158 setTextColor(Color.WHITE)` for the input-device list.
   *Fixed:* all settings labels now use `google_text_primary` / `google_text_secondary` /
   `google_accent`.
2. **Half the app is hard-coded dark, so a light theme looks broken.** Sidebars/dialogs use raw hex
   (`#141822`, `#1E293B`, `#0F172A`) while `bg_tv_left_sidebar` etc. are already theme-aware — so
   the same screen mixes light and dark surfaces. *Not yet fixed*: needs one new semantic palette
   (`surface_elevated`, `on_surface`, `on_surface_muted`) applied across ~14 layouts. See §5 W2.
3. **Search overlay (the Chrome "edit URL" screen) had a `+` icon on the *close* button** and a
   Google Lens button that just re-ran voice search. Backgrounds/text were pinned to
   `#131314`/`#E3E3E3`/`#9AA0A6` (dark-only) and the hint said "Search Google or type URL".
   *Fixed:* real back-arrow, Lens removed, theme-aware colours, `@string/search_or_type_url`,
   focus handed back to the page on close, suggestion list uses precise RecyclerView updates.
4. **Find-in-page was a stub.** `ChromeMenuPopup.showFindInPageDialog()` called
   `webView.findAllAsync(query)` and nothing else: no match count, no next/previous, no
   `clearMatches()` (highlights stayed), no `FindListener`. *Fixed:* `FindInPageDialog.kt` —
   debounced incremental search, "n of m" counter, prev/next, `IME_ACTION_SEARCH`/Enter,
   listener+matches cleaned up on dismiss, D-pad-focusable buttons.
5. **"Translate this page" was dead.** It built `https://translate.google.com/translate?sl=auto&tl=en&u=…`,
   an endpoint Google shut down years ago → every user landed on a "feature moved" page.
   *Fixed:* `PageTranslate.kt` uses the `*.translate.goog` page proxy Chrome itself uses,
   `_x_tr_pto=wapp` (so **no Google toolbar/account UI** is injected), language picker (24 languages,
   remembered in `Config.translateTargetLanguage`), and a "Show original" toggle.
6. **Safe Browsing was disabled in two places** — `WebViewEx` `safeBrowsingEnabled = false` **and**
   `AndroidManifest` `android.webkit.WebView.EnableSafeBrowsing=false` — while the README sells
   "the securest browser". Also `mixedContentMode = COMPATIBILITY_MODE` and `allowFileAccess = true`.
   *Partially fixed:* safe browsing now on by default with a real Settings switch
   (`Settings → Web Engine & Rendering → Safe Browsing protection`); mixed content / file access
   still to review (§5 W3) because `file://` loading is used by the built-in file manager.
7. **`QUERY_ALL_PACKAGES` (Play-restricted) was requested for no reason** — every package lookup in
   the app resolves `VIEW` / speech / install intents, which `<queries>` already covers.
   *Fixed:* permission removed, explicit `<queries>` added; plus a `network_security_config.xml`
   that pins the app's *own* endpoints (update checks, EasyList, gothwad.com) to TLS while leaving
   plain `http://` web browsing possible.
8. **Incognito activity could not survive a keyboard plug-in.** `.activity.IncognitoModeMainActivity`
   declared `configChanges="orientation|screenSize|screenLayout"` only — no `keyboard|keyboardHidden|
   navigation|uiMode|density|…`. On TV, connecting a USB keyboard (or a system dark-mode change)
   recreated the activity and destroyed the private session. *Fixed:* same configChanges as the main
   activity.

## 3. Findings — P1 (quality / perf / consistency)

9. **`onTrimMemory()` cleared the whole favicon cache on every backgrounding.** Condition was
   `level >= TRIM_MEMORY_RUNNING_LOW (10) || level >= TRIM_MEMORY_MODERATE (60)` — `TRIM_MEMORY_UI_HIDDEN`
   is 20, so it always matched → favicons re-decoded on every return to the app. *Fixed* (now only on
   `RUNNING_CRITICAL`/`BACKGROUND`/`MODERATE`/`COMPLETE`).
10. **Connectivity via a deprecated broadcast.** `onResume` registered `android.net.conn.CONNECTIVITY_CHANGE`
    (deprecated at API 28, unreliable/delayed on many TV boxes) and read `activeNetworkInfo`
    (removed-ish since 29) → after Wi-Fi reconnect the WebView could keep thinking it was offline.
    *Fixed:* `registerDefaultNetworkCallback` + `Utils.isNetworkConnected()`, unregistered in `onDestroy`.
11. **`clearCache()` leaked a WebView.** `override suspend fun clearCache(ctx) { WebView(ctx).clearCache(true) }`
    — never destroyed, and a `WebView` constructor is not valid off the main thread (the caller
    coroutine could hop dispatchers). *Fixed:* `withContext(Dispatchers.Main)` + `try/finally destroy()`.
12. **`offscreenPreRaster = true` for every live tab.** Chromium allocates an extra painted buffer per
    tab; with `maxLiveTabs = 6` that's exactly the memory a 1–2 GB box cannot spare. *Fixed:* on only
    while the tab is attached (`onAttachedToWindow`/`onDetachedFromWindow`).
13. **Home-screen dashboard burned CPU on the UI thread.** `NativeHomeView` ticked every 1000ms on a
    main-thread `Handler` and inside that tick did `ActivityManager.getMemoryInfo()` (IPC) +
    `StatFs` (syscall) + `TrafficStats` + `notifyItemRangeChanged`. *Fixed:* sampling moved to
    `Dispatchers.Default`, storage only every 5th tick, ticks skipped when not visible or when the
    previous sample is still running, scope cancelled on detach.
    *Still to do:* the "⚡ RAM Boosted" card calls `System.gc()` twice and toasts a "freed" number
    (`NativeHomeView.kt:435-444`). That is snake oil — Android forbids advertising GC as a
    performance feature and Chrome has no such thing. Recommendation: replace the card with a real
    "Memory & tabs" panel (live RSS, per-tab WebView count, a working "Discard background tabs"
    action = `TabsModel.onTrimMemory()`). Tracked as §5 W4.
14. **Desktop mode is global, not per tab.** `WebViewEx.isDesktopModeEnabled()` returns
    `config.isDesktopMode()`; `PageZoomController` and `TabsModel` therefore apply the desktop
    viewport/UA of *one* tab to *all* tabs, and the menu checkbox ("Desktop site") flips every tab.
    Chrome's is per-tab — and `HostConfig` already exists in the DB, so the plumbing is half there.
    *Not fixed in this pass* (touches `WebTabState`, `TabsModel`, menu, zoom controller): §5 W5.
15. **`Home` button destroys the tab.** `showHomeScreen()` sets `currentTab.url = HOME_URL_ALIAS`,
    `clearHistory()` and loads `about:blank`, then fakes "forward" via `lastUrlBeforeHome`. Pressing
    Home on a form-filled page loses the page *and* its back-history — Chrome's home button does
    neither. *Not fixed* (the `url` field is read in ~8 places; needs a `isHomeOverlayShown` flag
    instead): §5 W6.
16. **README/roadmap claims the code can't back yet** (this is what makes it look "incomplete"):
    * "< 10 MB APK": no measurement in the repo; `largeHeap="true"`, Roboto-era assets, 4 mipmaps ×
      xxxhdpi PNGs and the whole adblock lib are in there. Also `ic_google_lens.xml` is now unused →
      delete it with the other orphans (`ivMiniatures`, `llMiniaturePlaceholder`, `progressBarGeneric`
      if unused, `TopTabsAdapter`'s duplicate new-tab id `ibTopNewTab` which is 0dp and gone).
    * "10+ languages with responsive 10-foot UI": `values/strings.xml` has 241 strings, every
      translation has ~160 → ~80 keys English-only, and **everything added since then** (settings
      categories, Chrome menu, sidebars, search overlay) is hard-coded English in Kotlin/XML.
    * "AdBlocker: Brave AdBlockClient engine": real (`libs.ad.block`) ✔ — keep.
    * "100+ real devices tested": there is no test harness in the repo (one `ExampleUnitTest.kt`,
      one `FaviconExtractorTest.kt`) and no CI job that runs anything but assemble
      (`.github/workflows/build_apk.yml`).
    * Store links: `github.com/Gothwad/gothwad-browser` (README) vs `github.com/gothwadtech/tvbrowser`
      (About screen) vs the real remote `github.com/GothwadTech/browser`; `gothwad.com` vs
      `gothwadtech.com`; support e-mail `pawangothwad@gmail.com` vs `gothwadtech@gmail.com`; the
      Play/JioStore badges point at listings that don't exist for `com.gothwad.browser` yet.
17. **AGENTS.md incident #17 is still open:** 16 `notifyDataSetChanged()` calls in 10 adapters
    (History, Downloads ×2, Favorites ×2, Tabs sidebar, tab switcher, shortcuts, search overlay ✔ now
    fixed). Rule 5 of AGENTS.md says they must go.

## 6. Verification checklist for this pass (run on a real phone + a real TV box)

Phone (portrait):
* [ ] Top row = pill only; bottom row = ← ⌂ + ▣(count) ⋮. Nothing overlaps at 360dp or at 600% font scale.
* [ ] Tabs badge count matches the tab grid; ← greys out on the home screen; back gesture still works.
* [ ] Landscape rotation & folding a 2-in-1 → layout switches to the full header, no empty bottom bar.
* [ ] Light theme **and** dark theme: settings labels readable; search overlay readable; ⋮ menu readable.
* [ ] Type a URL → suggestions appear; `Enter` navigates; `←` closes and the page regains focus.
* [ ] ⋮ → Find in page: counter updates while typing, ↑/↓ move matches, closing removes highlights, `Esc`/back closes.
* [ ] ⋮ → Translate this page → pick language → page loads translated **without** Google's banner;
      ⋮ → Translate again on that page → "Show original" returns to the exact source URL.
* [ ] Downloads still work (notification permission path), file upload dialog still works (`<queries>` change).
* [ ] Safe Browsing switch: with it ON, `testsafebrowsing.appspot.com` blocks the sample malware URL.

TV (Android TV / Fire TV / 1–2 GB box):
* [ ] D-pad: header ←/→ still cycles all controls, ↓ enters the page, ↑ at the very top returns to the header.
* [ ] "Toggle toolbar" shortcut (Ctrl+\` or whatever is bound in Settings → Shortcuts) now actually hides/shows the header.
* [ ] Top tab bar ON → tab bar + header, OFF → header only; no stray 28dp gap in phone mode.
* [ ] Home screen: no jank while cards update (compare `adb shell dumpsys gfxinfo` before/after), clock keeps ticking, cards stop when you leave home.
* [ ] USB keyboard plug/unplug in an incognito window → **no** restart of the private tabs.
* [ ] 8 tabs open, switch fast, no `onRenderProcessGone`; `adb shell dumpsys meminfo com.gothwad.browser` should show lower PSS than before on background tabs.
* [ ] Airplane-mode ON → OFF: page reloads without the app thinking it is still offline.

Build:
* [ ] `./gradlew :app:assembleDebug` in Android Studio (this sandbox cannot compile), then
      `./gradlew :app:lintRelease` — watch for the viewBinding id names
      (`ibBottomBack`, `ibBottomHome`, `ibBottomNewTab`, `flBottomTabsSwitcher`,
      `tvBottomTabCountBadge`, `llSafeBrowsing`, `scSafeBrowsing`).
